# 《灵魂匹配局：社区 × 社交》产品说明计划书

## 一、项目概述

“灵魂匹配局：社区 × 社交”是一个知乎数字分身社区原型。项目以 RPGJS 多人小镇作为可视化入口，以 FastAPI + 知乎开放平台能力作为知识与创作服务，以 Agent 和长期记忆作为分身的表达与关系引擎。

用户不是从一组孤立的 API 或聊天窗口开始，而是进入一个由知乎内容主题组织起来的世界：在热榜广场发现正在发生的议题，在藏书阁搜索和沉淀资料，在问道馆获得回答线索，在创作坊形成选题和草稿，在知我居认识自己的兴趣、人设与数字分身。项目希望探索一种新的知乎内容消费和创作方式：让“阅读—讨论—理解—表达”成为可持续的社交体验。

## 二、创作背景与问题定义

知乎社区积累了大量问题、回答、文章和专业经验，但用户在传统信息流中容易停留在单次浏览：看见热点，却未必找到可靠材料；有了想法，却难以组织成自己的表达；认识了观点相近的人，却缺少低门槛、具象的持续交流场景。

本项目聚焦三个问题：

1. 如何把知乎内容发现从“刷信息”转化为有目标的探索和对话？
2. 如何降低从阅读、提问到创作的转化成本，让用户更容易形成自己的观点？
3. 如何让数字分身不只是一次性问答，而能保留人设、偏好和共同交流的连续性？

## 三、核心创作思路

项目的核心不是把知乎页面搬进游戏，而是将知乎社区中的知识关系映射为空间关系和互动关系。

- **内容空间化**：用六栋功能建筑承载不同的知识行为。热榜是公共议题入口，藏书阁是资料检索入口，问道馆是问题理解入口，创作坊是表达生产入口，知我居是个人分身入口，天工坊预留结构化材料生产能力。
- **观点人格化**：每个玩家和居民都对应一个有兴趣、表达风格和记忆的数字分身。对话不只返回答案，也呈现不同的立场、语气和关系变化。
- **创作过程化**：用户从热榜或搜索发现主题，经由直答和资料整理形成理解，再由 Agent 协助生成知乎风格草稿，保留人工修改和继续讨论的空间。
- **多人关系化**：在线玩家、静态居民和托管分身共享同一世界；用户可以偶遇、交流和再次见面，形成比单次工具调用更有连续性的社区体验。

## 四、目标用户与产品定位

目标用户包括：希望快速了解热点并寻找可靠资料的知识消费者；有表达欲但需要结构化辅助的知乎创作者；对 AI 分身、兴趣匹配和新型社区交互感兴趣的年轻用户；希望以低成本验证 Agent 社区玩法的产品与开发者。

产品定位是“知乎知识社区的可探索数字分身实验场”，不是知乎官方客户端替代品，也不是自动代发内容工具。所有生成草稿都应由用户审核、修改并自行决定是否发布。

## 五、核心使用场景与用户流程

### 场景 A：从热点进入问题探索

用户在热榜建筑查看实时议题，选择感兴趣的主题后进入搜索或知乎直答，获得社区观点与外部材料的组合线索，再与附近分身讨论不同看法。

### 场景 B：从想法形成创作草稿

用户在创作坊输入一个尚未成形的想法，选择“知乎回答”或“知乎文章”目标，并指定清晰、幽默或严肃等语气。Agent 结合用户人设和参考材料生成结构化草稿，用户继续追问、修订和完善。

### 场景 C：认识自己的数字分身

用户在知我居触发知乎数据冷启动（需授权），系统从本人创作、收藏和关注中抽取兴趣领域、表达风格和观点摘要，形成可查看、可刷新的人设卡。关注数据只用于兴趣抽取，不自动建立关系。

### 场景 D：持续的分身社交

用户靠近在线玩家或居民后发起对话。系统按“主人私有记忆”和“双方共享记忆”隔离保存事实、偏好、共同经历与关系变化，使再次相遇时的交流具有连续性，同时避免跨用户泄露隐私。

## 六、与知乎社区生态的契合度

项目将知乎生态价值落在真实使用场景，而不是仅在界面上展示品牌：

- **内容生态**：通过知乎热榜、知乎搜索、问题推荐和知乎直答，把社区正在讨论的问题作为世界中的公共事件和探索入口。
- **创作者生态**：通过选题、参考资料和草稿生成，帮助用户从阅读者过渡为回答者和文章作者；产品不自动发布，尊重作者的最终编辑权。
- **知识质量**：公共内容与全网内容分开检索和呈现，保留来源链接；直答用于快速获得综合线索，深度研究仍回到原始来源。
- **用户关系**：以兴趣和观点为基础促成分身交流，强调“因内容相遇”，而不是泛化的陌生人社交。
- **开放平台边界**：公共能力由服务端统一封装；涉及创作、关注、收藏等个人数据时通过 OAuth 明确授权，并按最小范围读取。

项目对知乎的潜在价值在于：提供一种更具沉浸感的内容发现入口，延长高质量内容的讨论链路，降低用户参与创作的门槛，并为未来的知识 Agent、兴趣关系和创作者工具提供可验证的交互样本。

## 七、产品功能设计

当前运行小镇为 64×48 格连续地图，包含中央广场、南侧环路和六栋可交互建筑。建筑功能面板统一展示能力状态：`ready`、`unconfigured`、`auth_required`、`coming_soon`，避免把未接通能力伪装成可用功能。

已接通的核心能力包括：知乎热榜、知乎搜索、全网搜索、问题推荐、知乎直答、选题与草稿生成、Agent 对话、数字分身人设、在线多人同步和托管分身巡游。PvP 动作战斗属于世界交互实验能力，不参与知乎内容权限，也不影响地标和知识工具的安全边界。

## 八、整体技术实现方案

```text
浏览器 RPGJS Client ⇄ RPGJS Node Server
                         ├─ 地图、碰撞、移动与多人房间权威
                         └─ 在线玩家、托管分身与状态同步

浏览器 / 未来 Agent Runtime ⇄ FastAPI
                                ├─ 知乎 Tool Registry 与 REST API
                                ├─ LangGraph ReAct Agent Loop
                                ├─ OAuth 契约与个人数据边界
                                └─ Mem0 + SQLite 长期记忆
```

RPGJS 服务端负责游戏世界权威，不由 FastAPI 保存地图、房间或移动状态；FastAPI 负责知识能力、创作能力和 Agent 推理。两者通过明确的 HTTP/客户端交互契约协作，便于未来替换前端或接入其他 Agent Runtime。

知乎能力通过共享领域模型和 Tool Registry 暴露。当前公共工具包括热榜、知乎搜索、全网搜索、问题推荐、知乎直答和草稿生成；个人数据工具包括本人创作、关注、收藏、收藏夹和创作统计。Agent 根据访问者与目标分身关系限制可用工具，访问他人分身时不开放个人数据工具。

Agent 使用 LangGraph ReAct Loop 按需调用工具；Mem0 语义记忆与 avatar.db 结构化记录共同实现两级记忆：`avatar:{id}` 保存主人私有事实，`pair:{min}-{max}` 保存双方共享经历。记忆初始化、模型不可用或知乎未配置时均可降级，核心地图和基础对话不被单点服务阻断。

## 九、知乎开放平台与安全方案

Access Secret 只保存在后端或部署平台 Secret 中，浏览器不接触凭证。公共内容调用由 FastAPI 统一完成；OAuth 个人数据入口在用户明确授权后启用，并区分 App ID、App Key、Access Secret 和 OAuth Token。

产品遵循以下原则：个人数据最小读取；关注仅作为兴趣信号，不自动建立联系人；主人记忆与双方记忆严格隔离；不把服务端凭证所属账号误称为当前 Mock 用户；草稿默认不自动发布；日志不记录密钥和回调敏感参数。生产上线前还需完成 RPGJS 权威侧的身份绑定、防会话接管、限速、断线回收和房间 TTL。

## 十、当前 MVP 与验证情况

当前已完成：多人 RPGJS 世界及连续地图；六栋建筑和门口交互；知乎公共内容 Tool Registry；Agent 聊天与高层行为意图；三种 Mock 分身；登录和身份同步；人设冷启动；可关闭、可降级的长期记忆；托管分身巡游；基础动作战斗反馈。

已进行的验证包括后端单元测试、前端构建、地图碰撞和树木布局检查、桌面与 390px 窄屏浏览器检查，以及多客户端进入同一 RPGJS 房间后的玩家同步。当前项目仍是 MVP，OAuth 正式授权、内容详情/评论、完整创作统计和天工坊 PDF/PPT 异步任务属于后续阶段。

## 十一、创新点与项目价值

1. 将知乎的内容结构映射为可行走的知识空间，探索“空间化内容社区”。
2. 将数字分身的人设、关系和长期记忆放入多人世界，而非单一聊天窗口。
3. 以“发现议题—获取材料—交流观点—生成草稿”串起知乎消费与创作闭环。
4. 通过 Tool Registry、OAuth 边界和可降级设计，把实验性 AI 体验建立在可替换、可审计的工程基础上。

## 十二、版本规划

- **阶段一（当前 MVP）**：完成多人小镇、公共知乎能力、Agent 对话和基础记忆体验。
- **阶段二（个人化）**：完成知乎 OAuth，接入本人创作、关注、收藏和创作统计，完善人设冷启动。
- **阶段三（创作增强）**：补齐问题回答、内容详情、评论、单篇创作统计，并增强引用和草稿编辑链路。
- **阶段四（知识生产）**：接入藏书阁知识库以及天工坊 PDF/PPT 异步生成、轮询和下载。
- **阶段五（社区治理）**：完善身份绑定、隐私设置、内容审核提示、关系管理和世界服务的限速与生命周期治理。

## 十三、初审 Demo 展示建议

建议用一条连续路径展示项目价值：游客登录 → 进入中央广场 → 查看热榜 → 进入藏书阁搜索 → 在问道馆调用直答 → 与居民讨论观点 → 在创作坊生成草稿 → 回到知我居查看人设与记忆。展示时明确区分已实现、需授权和规划中的能力，并以知乎原始来源链接和后端权限边界说明可信度与合规性。
